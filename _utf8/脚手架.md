# 七、Java代码包说明

## 1. model

路径：

```
model/
```

职责：

保存游戏数据对象。

例如：

```
Crop

Soil

Farm

Player

Decoration
```

原则：

Model只保存状态。

不包含：

- 游戏计算
- 数据库操作
- UI逻辑

---

# 2. service

路径：

```
service/
```

职责：

负责游戏业务。

例如：

```
GrowthService

WeatherService

HarvestService

SaveService
```

Service负责：

- 状态变化
- 游戏流程
- 规则调用

---

# 3. dao

路径：

```
dao/
```

职责：

数据库访问。

例如：

```
CropDAO

SoilDAO

PlayerDAO
```

负责：

- 查询
- 保存
- 更新
- 删除

不负责：

- 游戏规则判断

---

# 4. controller

路径：

```
controller/
```

职责：

连接：

View

和

Service

例如：

```
FarmController

ShopController
```

负责：

- 接收用户操作
- 调用Service
- 刷新界面

---

# 5. view

路径：

```
view/
```

职责：

JavaFX界面。

例如：

```
FarmView

MainView

CollectionView
```

负责：

- 显示
- 输入交互

---

# 6. factory

路径：

```
factory/
```

职责：

对象创建。

例如：

```
CropFactory

DecorationFactory
```

---

# 7. manager

路径：

```
manager/
```

职责：

项目级管理。

例如：

```
GameManager

SceneManager
```

---

# 8. util

路径：

```
util/
```

职责：

通用工具。

例如：

```
JsonConfigLoader

RandomUtil

AnimationUtil
```

---

# 9. 接口与实现类拆分约定

核心实体与服务统一按“接口 + 实现类”拆分：

- 接口定义在包根（model、service）；
- 实现类以 Basic 前缀置于 impl 子包（model.impl、service.impl）；
- 枚举不拆分。

# 十六、后续开发原则

所有新增代码必须遵守：

```
界面需求

↓

Controller

↓

Service

↓

DAO

↓

- View直接修改Model
- DAO包含业务判断
- Model包含复杂逻辑

# 十八、最终说明

本脚手架的目标：

不是提前实现游戏。

而是建立一个稳定工程基础，使团队能够在统一结构下持续开发。

后续所有功能：

必须在此结构上扩展。

不得重新建立新的目录体系或技术路线。
